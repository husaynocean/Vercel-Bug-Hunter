How it works

From your repo to proven findings

  1. Lock the scope

    You name the commit and the files. Nothing outside that list is analysed.

  2. Scan

    Slither and Semgrep run first to surface leads.

  3. Review every function

    Each external and public function is checked for access control, reentrancy, rounding, oracle manipulation, accounting, integration, denial of service and standards bugs.

  4. Prove it

    Each suspected bug gets a Foundry test. It must pass on your code and fail once the suggested fix is applied. Anything that cannot be proven is dropped.

  5. Report

    You get a write-up per finding: root cause, impact, the test, and a fix as a diff. I review every finding by hand before it reaches you.

Sample finding

What a finding looks like

Reproduced on the public Canto asD contest (Code4rena, November 2023), where this bug was a confirmed High. It is one of the bugs the AI could not recite from memory. Shortened from the full report.

High · Integration

The exchange rate is scaled for the wrong decimals, so the owner's interest is locked forever

asD.sol · withdrawCarry() · L72–L90

Root cause. The contract divides the cNOTE exchange rate by 1e28, the scale for a Compound cToken with 8 decimals. On Canto, cNOTE has 18 decimals, so the rate is scaled by 1e18. The NOTE backing is understated by a factor of 10 billion and the subtraction of the asD supply underflows.

Impact. withdrawCarry reverts whenever any asD exists, so the creator can never withdraw the interest the protocol is built to pay them. It happens in normal use, with no attacker, and the contract has no other way out.

// asD.sol, withdrawCarry()
uint256 maximumWithdrawable =
    (cNote.balanceOf(address(this)) * exchangeRate)
    / 1e28 - totalSupply();   // underflows: rate is 1e18-scaled
// fix
-            1e28 -
+            1e18 -

The test passes on the audited commit and fails once the fix is applied.
